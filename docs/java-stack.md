# 개발 언어를 Java로 바꾸면서 기획서에서 고칠 부분

기획서 초안은 Python(Django·pycryptodome·Celery) 기준이다. 코어를 Java 21로 구현했으므로
제출 전 아래 항목을 바꿔야 기획서와 코드가 어긋나지 않는다.

## 기본정보

- 개발언어: **Java 21**

## ❷-3 ② 봉인

- "pycryptodome의 Shamir는 16바이트 비밀만 다루므로 32바이트 키를 16바이트 두 덩어리로 나눠 각각 분산합니다" → 삭제.
  사용한 라이브러리(`com.codahale:shamir`)는 GF(256) 위에서 바이트 단위로 분산하므로 32바이트 키를 그대로 2-of-3으로 나눈다.
- AES-256-GCM, Ed25519는 JDK 표준 암호 API(JCA)로 구현한다.

## ❷-9 서비스 자체의 보안 설계

- 코딩 기준: "Python 시큐어코딩 가이드" → **행정안전부 JAVA 시큐어코딩 가이드**.
- 표에서 바꿀 행:

| 보안약점 | 비상봉투에서의 위협 | 대응 |
|---|---|---|
| 신뢰할 수 없는 데이터의 역직렬화 | 작업 큐 메시지 조작 | `ObjectInputStream` 미사용, JSON 메시지 + Jackson 기본 타입 지정(default typing) 비활성, 서명·AAD 입력은 길이 접두 인코딩 |

## 구현하면서 설계를 보강한 점 (기획서에 반영 권장)

1. **확장 A의 등급은 가구마다 다르다.** 동행파트너는 자기 담당 가구에선 지정 조력자, 다른 가구에선 확장 A다.
   보관 기관은 요청자가 주장한 등급을 믿지 않고 자격 명부와 지정 관계로 직접 계산한다.
2. **"예보 + 건물 고위험" 공개의 증거 형식.** 보관 기관이 이를 독립 검증하려면 근거가 필요하므로,
   정책 엔진이 서명한 앞당기기 선언을 공식 예보와 **함께** 제출하게 했다. 앞당기기 단독으로는 열 수 없어
   ④의 원칙("분석 엔진이 오염돼도 맑은 날에는 아무것도 열리지 않습니다")이 코드로 보장된다.
3. **nonce 재전송 방지의 위치.** 한 경보는 여러 가구 개봉의 근거가 되므로, nonce 1회 사용은 수신 시점에,
   보관 기관은 유효 시간·격자 일치로 제한한다.
4. **가정 기기가 없는 가구의 도착 확인.** 확장 A는 위치만으로 도착 인정, 확장 B는 도착 확인 불가(방향·필요 유형까지만).
5. **위험도 임계값.** 건물 정적 조건 합계(최대 0.65)가 임계값(0.7)을 넘지 않게 해, 실제 강우 없이 앞당기는 일이 없게 했다.
